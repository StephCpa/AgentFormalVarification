记录日期：2026-10-26。依据：工作区详细设计 v0.1。当前阶段为 M1 实现中；下表的“参考实现”均不包含生产部署保证。原研究文件中的 54 状态结果没有源模型可供复现，本原型的状态统计独立命名，不能替代原结果。

## 当前交付与验证

- 退款参考内核：绑定租户、主体、任务、业务键、订单/版本、目的地、金额/费用、政策/epoch、三个授权引用和许可有效期。
- 双账户预留：租户账本承诺本金加手续费，订单账本承诺本金；任一账户失败不提交另一账户。
- 结果/结算分离：`Unknown` 保留承诺；业务成功且费用未终结时仍保留费用额度；实际超界先记账再隔离。
- 独立远端模拟器：条件版本检查、稳定操作键、实际效果与终态拒绝墓碑。
- 有限模型：2 个操作、金额 70/60、预算 100、至多一次撤销、无费用、无崩溃、永久去重。正确模型 114 个可达状态、445 条有向转移（含幂等自环）；每条边通过一条最短代表前缀回放到 Python，比较抽象状态、累计成本、承诺和准入计数。不是所有具体历史的机械精化证明。
- 两个变异 oracle：分离检查/提交模型找到 70+60 超额预留；超时释放模型找到真实成本 70 而本地承诺为 0。测试断言确实发现反例，防止检查器空洞通过。
- Lean 4.33.0：P1/P2 抽象准入历史、P3 多账户正常转移保持，以及 P7 权限包含/祖先撤销门禁/共同账本组合核心已通过内核检查。P7 包含非空准入、预留与结算实例，见 [委派形式化规格](formal-delegation-profile.md)。依赖和范围见后文。
- P4 抽象条件桥接：独立真实费用、部分观察、全成本终局与正常预算组合；任意有限操作序列的归纳证明、非空迟到手续费实例，以及单操作 41 状态/135 转移的独立模型和四种变异反例。适配器真实性、完整上界与 Python/SQL 精化仍须另证，见 [成本桥接规格](formal-cost-bridge-profile.md)。

## Lean 结论与依赖

`P3_budget_preserved`：对任意账户个数、任意有限正常转移序列，若初始每账户 `spent + pending ≤ limit`，且每次预留先检查所有账户，每次结算满足 `charge + residual ≤ old` 且 `old ≤ pending`，则末态仍逐账户满足预算。Unknown 定义为保持状态。事故费用违反上述前提，走单独记录分支，不属于该定理。

`P1_P2_admission`：从授权历史有效且许可无重复的初态，经过新鲜许可且当前 epoch 满足抽象 `authorized` 谓词的准入、撤销和幂等重试，历史保持授权有效且许可唯一。它证明模型门禁保持性质，不证明 `authorized` 谓词来源真实，也不证明 Python 的 `_authorize` 等价于该谓词。

P7_composition：在合法衰减链、初态安全/唯一/额度绑定、固定限额及逐次全账户守卫下，任意有限执行保持叶权限包含、各祖先声明额度和共同根总承诺上界。逻辑操作逐项计数，根与子额度视图不相加；超界成本、实际观察权威性和实现精化不在该定理中。

`P4_actual_within_budget`：若初态合法、记录唯一且满足预算，远端计费受完整 upper 约束，部分观察单调且不超实际成本，终局观察等于全部实际成本并保证以后不能新增费用，则任意有限正常执行保持 `Σactual ≤ Σ(spent + remaining) ≤ limit`。适配器违约不在正常定理范围内；事故费用仍必须记录并隔离。

Lean 实际公理依赖：P3 为 `propext, Quot.sound`；P1/P2 为 `propext`；P4 三项一般定理为 `propext, Quot.sound`；P7 权限传递为 `propext`，祖先撤销门禁无公理依赖，共同预算及组合为 `propext, Quot.sound`。没有自定义公理或 `sorryAx`。验证脚本要求真实依赖记录完整且不重复，依赖只允许当前白名单；原始输出与解析结果留档。Python/SQL 到 Lean 的 refinement、真实适配器对 P4 前提的履行，以及 P5—P8 完整系统证明仍未完成。
