# 发送窗口、有限去重保留与迟到报文

状态：2026-10-26，固定退款原型 `refund-send/0.1`。落实详细设计 §13.2 重试资格、§13.3 终局无效果及 T18。数据库沿用 schema v8，冻结操作及已有审计事件足以保存本版窗口与尝试次数，不新增可重置的计数副本。

## 不变量与期限

发送端检查不能阻止已经离开发送端、尚未到达远端的报文。有限去重服务必须同时满足：去重记录覆盖该逻辑操作的整个可接受报文窗口；窗口关闭后，即使去重记录已删除，远端也拒绝旧报文。

本版将冻结的 `Operation.expires` 同时用作报文接受截止 `not_after`。它已包含在许可 binding 中，不由重试节点重新计算。这是固定退款原型的保守选择，不代表授权到期会取消已经接受的外部效果。之前发生的费用、Unknown、核对义务及权威回执在截止后仍然有效。

|参数|本版规则|
|---|---|
|发送配置|固定 `refund-send/0.1`，不可由 Agent 覆盖|
|接受截止|冻结 `op.expires`，重试不延长|
|本地余量|要求 `now + 1 < not_after`；1 为逻辑时钟单位|
|发送次数|每逻辑操作至多 3 次 SendAttemptAdmitted；包括发送意图已提交但未执行的尝试|
|请求身份|同一 operation_id、完整请求、接收者与 binding；不产生替代操作|
|重试费用|固定模拟退款服务的同键重复请求不新增费用；收费重试未实现|
|远端有限保留|可选 `retention_seconds` 和显式单调时钟；首次记录固定期限，重试不滑动续期|
|新记录接受条件|`now < not_after ≤ now + retention_seconds`；不满足时拒绝且无效果|
|记录到期|删除去重记录与墓碑；审计用真实效果 oracle 仍保留，但 query 不读取它|

逻辑时钟测试不证明真实网络、跨主机时间误差或 UTC 安全余量。基础模拟模式接收受信宿主 Operation；可选 [发送鉴权模式](send-envelope-profile.md) 核验 HMAC JSON 信封，拒绝参数或截止篡改。完整部署仍需生产身份、凭据/出口隔离，以及可验证的保留与时间契约。不能把 Python 对象的不可变字段或普通摘要当成网络来源认证。

## 发送端实现与事务

[`sending.py`](../avcl/sending.py) 统一检查准入、binding、时间、历史次数并记录 SendAttemptAdmitted。时间戳、截止、配置版本和次数写入已有审计事件，PostgreSQL 在恢复时读取历史，不能靠更换 worker、run_id 或重新启动服务清零。内存检查在内核锁内，持久检查在同一 SERIALIZABLE/tenant guard 事务内完成。

以下入口均调用共同门禁：内存工作流 Send、持久工作流 Send、PostgresKernel.claim_outbox。原始 RefundService.send 是受信测试适配器入口，不是公开 Agent API，直接持有它不受本地发送次数约束。

PostgresKernel.claim_outbox 现在先处理 `wait_until ≤ now` 的待发送行：登记 Unknown、保留预算和核对义务，不再要求 reaper 先运行才能阻止迟到领取。它可以跳过已过期的候选行；被共同发送门禁拒绝的操作提交为 NeedsReconcile，后续领取不会再次发送该行。

窗口或次数耗尽时，SendBlocked 与 Unknown/义务同事务提交，不通过抛出异常回滚这些必要事实。工作流继续执行已有 Reconcile；结束状态 Finished 仍不代表业务成功。假设健康检查仍保留在原发送准入事务中。

持久工作流和 outbox 对已领取的不确定写入仍采用核对恢复，不自动重发。3 次上限不是自动重试承诺；它也约束内存工作流中的多个显式 Send。无请求的网络库自动重试未启用。若未来允许持久重发，必须继续使用同一门禁，并单独实现租约所有权与费用预留协议。

## 远端有限保留实现

[`RefundService`](../avcl/simulator.py) 默认保留原有永久去重行为，以维持既有模型与示例的边界；显式指定有限保留时，send、query、cancel 都使用同一远端时钟，并真实清理到期记录。时钟回退拒绝，重复报文不会续期。

有限模式的 send 与取消墓碑入口都在产生效果前检查报文截止。已过期请求返回 REMOTE_ACCEPTANCE_CLOSED；配置的保留期不足以覆盖报文接受窗口时返回 REMOTE_RETENTION_TOO_SHORT。两者仅说明这次请求被拒绝，不能证明历史没有效果，所以执行器继续保留 Unknown，不能据此释放费用，也不将正常窗口拒绝误报为适配器内部异常并隔离租户。

去重记录过期后 query 返回 None，即使独立效果 oracle 知道之前执行过。宿主不能把这种缺失变成 RejectedNoEffect。此前独立保存的权威回执仍可结算；否则继续核对或转交。新的客户端 request_id 也不能绕过本地未决业务动作键生成替代操作。

## 验证证据与范围

单元测试覆盖成功回执丢失、同键重发、实际删除记录、取消墓碑到期、重试不延长 TTL、窗口余量、时钟回退、尝试次数耗尽、迟到 worker 及无记录保留预算。真实 PostgreSQL 测试覆盖：

1. 未运行 reaper 时拒绝过期 outbox 领取，并提交 Unknown 与义务。
2. outbox 尚有效但报文窗口不足时拒绝领取。
3. 领取提交后进程退出、远端效果后丢回执、远端记录过期、数据库重开后不再发写请求；迟到权威回执仍可结算。
4. 独立连接同时领取只提交一个发送意图。
5. 持久工作流截止后只核对，以及已领取的迟到报文被远端拒绝时不误隔离。
6. 已记录截止拒绝后的时钟回退不会重新开放领取。

独立 [`send_window_model.py`](../models/send_window_model.py) 有 90 个状态、204 条转移，单逻辑操作、最多两个报文、时间 0..4、接受截止 2、保留两单位。正常模型没有重复效果或预算覆盖反例。模型不使用订单版本保护，直接检查发送/到达分离与去重期限。

三个变异分别产生：过期发送准入、远端漏截止导致第二次效果、查询缺失错误释放后现实费用失去覆盖。尤其第二种反例先在期限内放行两个报文，第一个执行后记录过期，第二个才到达；它说明只检查发送端不足以保证安全。有限模型未覆盖任意消息数量、所有真实时间误差或数据库精化。

运行 `verify.cmd --postgres`，以对应验证报告、send-window-model.json、单元及真实数据库日志为验收依据。原有永久去重预算模型的 114 状态统计不变，不能将新模型统计冒充完整系统状态数。

## 后续边界

本版补上有限保留模拟协议及宿主发送门禁；本地 HMAC 信封已作为可选模式接入。生产端仍缺身份/endpoint 绑定、密钥隔离、真实服务 TTL 合同、跨主机可信时间、收费重试与维护预算、持久远端服务重启、备份恢复 epoch 和全中介部署。既有过期/未知操作不会因升级本版自动获准新写入，也不会清理其承诺或历史。
