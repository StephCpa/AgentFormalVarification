# 回执鉴权与恢复

状态：2026-10-26，`avcl/receipt-envelope/0.1`。本地 HMAC 原型覆盖发送结果、只读核对、结算与原始回执恢复；对应 R02/R05/R14 和 T02/T05/T14/T17。它验证消息来源和绑定，不证明服务端声明的费用或终局事实必然真实。

## 回执的内容与密钥

[`receipt_envelope.py`](../avcl/receipt_envelope.py) 对精确字段集鉴权：format、key_id、tenant、issuer、operation_id、request_digest、binding、observed_at、observation_id、kind、cumulative_costs、final_cost、terminal_effect。鉴权码覆盖所有字段，累计费用采用规范十进制字符串，终局标记必须是布尔值。

回执密钥由同一测试 authority 主密钥按独立的 `avcl/receipt-key/0.1` 域和租户/接收者派生，MAC 使用 `avcl/receipt-authentication/0.1` 域。发送、回执和政策的密钥用途分开，持有发送验证密钥不能直接生成有效回执。宿主配置的鉴权模拟服务同时获得请求验证器和回执签发器；其共享密钥、进程与数据库仍处于测试信任域内。

接收端先核对 MAC、租户与 issuer，再比较预期操作编号、已登记操作的完整 binding 和 request_digest。只允许已准入操作的 Confirmed、RejectedNoEffect、PartialEffect 观察，费用维度限定为租户总费用和当前订单本金；委派额度由已有内核映射派生，远端不能额外声明祖先账户造成重复计费。

相同观察 id 的相同事实保持幂等，改变其内容仍触发已有争议规则。合法鉴权不放宽累计费用单调、结果一致性、费用上界或终局条件：带正确 MAC 的超界费用仍入账并隔离，不能为维持不等式截断费用。

不同 id 的相同终局结果和累计费用也不能撤回已建立的 Final：较弱旧证据追加记录为 ObservationSubsumed，不重建预留、义务或任务未决投影。累计费用独立接受最多 19 位规范十进制数，覆盖两个 18 位请求分量的合法总和；请求与时间域保持原限制。签发、解码及异常域边界见 [F1/F3 修复规格](review-fixes-profile.md)。

费用向量按账户索引比较，不把列表序列化顺序当成不同费用事实。旧本地 Observation 与新鉴权 JSON 的账户顺序可能不同；同 id、同费用和同结果应保持幂等。比较时规范化顺序，原有冻结 Observation 与审计记录不重写；费用数值或其他事实字段改变仍产生争议。

## 发送期限与证据时刻

发送信封限制何时还能接受新的请求，回执证明已发生的事实。回执没有沿用发送截止作为接收有效期：即使发送窗口、当前政策或远端去重记录已经过期，保存完好的历史回执仍可核验并结算。

observed_at 不能晚于接收端当前逻辑时间。未来事实会被拒绝并保留承诺；时间达到后可以重新提交同一原始回执。成功接收不会自动清除此前的隔离事故。真实跨主机时钟误差、历史密钥轮换与失陷后的证据接受规则仍待设计和验证。

## 防止重启后降级

AuthenticatedReceiptRequired 是操作上的单调审计事实，一旦记录，普通 Observation 对象不能再作为该操作的结算输入。它与操作/账本同事务持久化，不因更换 worker 或重开数据库消失。

- 内存鉴权工作流在 Prepare 时绑定该要求。
- 持久工作流在 WorkflowStarted 事件中冻结鉴权模式，Prepare 时将要求绑定到操作。恢复者即使没有原适配器对象，也必须接受鉴权回执；更换成不匹配的适配器模式会被拒绝。
- 独立 outbox 消费者用 `claim_outbox(..., authenticated_receipts=True)` 在领取事务中绑定要求；返回值报告当前绑定。默认 False 保留原有受信本地模式，不能清除已绑定要求。
- 监督器使用鉴权服务时，在查询前绑定要求。成功核验的鉴权回执也会绑定该操作，避免后续意外降级。

旧工作流事件没有模式字段时按原有受信本地模式解释。原始 Observation 仍是未绑定操作的宿主接口，不是公开客户端入口。不能把本地兼容模式误称为生产鉴权配置；正式工具注册与发布门禁仍须接入这些要求。

## 原始输入先落盘，恢复后再核验

PostgresTrusted.observe 对鉴权回执或显式指定预期操作的输入，保存闭合编码三元组 `(avcl/observation-input/0.1, expected_operation_id, raw_receipt)`。它复用原有 observation_receipt 表，无 schema 迁移；旧的原始 Observation 记录仍可恢复。

必须一起保存 expected_operation_id：若一个操作的有效回执被错误地交给另一个工作流，即使此时进程在原始输入提交后退出，恢复也必须继续拒绝该不匹配，而不能丢弃上下文后把它当作无上下文回执应用。

原始输入独立提交后，结算事务重新核验 MAC 与当前持久操作，再应用账本。验证失败保留原始输入及 observation_application 的拒绝原因，独立提交隔离事件，避免回滚一并抹去事故。拒绝记录不阻塞后续待恢复回执；后来取得的真实证据仍能结算，隔离状态保持。

原始输入使用现有 64 KiB 闭合存储编码限制。超过编码上限、无法编码的输入在持久化前拒绝；“原始输入保留”只适用于该存储协议可接收的有界输入，不承诺无限保存攻击流量。

## 工作流与监督行为

鉴权模拟服务的 send/query 返回稳定的鉴权 JSON；同一事实的重复查询不生成新观察 id 或重复费用。删除远端去重记录时一并删除可查询的回执缓存，但宿主已保存的回执仍有效。None 只表示没有权威证据，不能生成无效果终局。

两个工作流后端把预期操作编号传入 TrustedPlane.observe。错误鉴权、跨操作绑定或未鉴权降级会停止该工作流、保留预算并隔离新增支出。监督器对这类回执记录拒绝并延期核对，保持未解决义务；没有因为“收到响应”就宣告任务完成。

## 验收与范围

单元测试覆盖字段篡改、发送/政策密钥不能伪造回执、跨操作重放、普通对象降级、未来时刻、发送期限后的迟到证据、部分费用后最终结算、同 id 冲突、带鉴权的超界成本，以及工作流查询恢复。

真实 PostgreSQL 测试覆盖原始鉴权回执提交后进程退出、预期操作上下文恢复、拒绝记录不阻塞后续真实证据、鉴权要求跨重启保留、无适配器对象的工作流恢复、模式切换拒绝，以及监督器接收真实/拒绝伪造查询结果。

`send-envelope-demo` 的报告升级为 0.2，新增伪造回执被拒绝而真实费用继续受承诺覆盖的轨迹。验证日志现在随子进程输出直接写入文件；失败或超时时保留之前已产生的输出和错误标记，避免只留下超时字符串。最终结果仍以对应 verification.json 的阶段退出码、证明门禁和源码摘要为准。

HMAC 共享密钥持有者仍可生成同域消息，消息鉴权不能证明远端未撒谎。当前没有生产 KMS/TLS、真实服务身份、密钥轮换、认证取消协议、远端持久化重启或 Python/SQL 精化证明；P4 的适配器真实性与终局可靠性前提仍需独立建立。
