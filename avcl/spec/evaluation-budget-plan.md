# 运行求值预算：原实施方案记录

本文件保留实施前的设计推导，**不是验收证据**。当前实现与工作单位以[有界运行求值规格](evaluation-budget-profile.md)为准；特别是 If 真分支汇合与 VM JUMP 均计费。静态 AST/类型上限和离线求解器预算仍不能替代运行门禁。

定量动机见 `evidence/20261026T115016.527975Z/evaluation-work-probe.json`：相同 3 节点 Eq 表达式，合法集合输入从 1 增至 64 个八字段记录时，规范化调用由 20 增至 1154，扫描字符串由 512 增至 32768 字符；最大输入规范编码为 41236 字节，仍低于 64 KiB。AST 与 VM 都接受这些输入。探针只计规范化，不含哈希、比较和指令工作，不作为时间上界或拒绝机制的证据。

## 预算范围与结果

采用宿主分配的确定性工作量计数器，包含限额、已用量和耗尽状态。不允许候选请求提高限额或重置计数器。单次 prepare/dispatch 的内置退款检查与全部匹配合约条款共享预算，不能通过拆成多条款获得重复额度。直接纯谓词求值也有默认限额；测试可由宿主设置较小限额以覆盖边界。默认数值须以现有合法案例及最坏结构探针校准，文档记录单位和上限，不把该数值解释成毫秒。

耗尽返回明确的 UnknownEvaluation 原因，属性状态为 Unknown，当前授权动作拒绝。不得将“未完成检查”视作 false 从而误报 Violated，也不能利用 forbid 的取反使失败转为允许。若预算在 dispatch 耗尽，已有 Prepared 操作、许可和全部预留保持；prepare 耗尽则无新操作、批准消费、去重记录或账本增量。数据库沿用事务回滚，且不得发布 outbox 发送意图。

## 所有工作都必须有界

1. 先检查原始输入的类型、容器长度、字段数量等廉价边界，再遍历内容。当前 Record 规范化会先检查全部 entries；必须防止巨量非法 entries 在预算计数前被扫描或复制。
2. 对输入规范化中的每个值节点、字段键、字符串长度和整数位宽计费。递归规范化必须共享计数器；不能用每个元素重新创建预算的方式处理嵌套 Set/Record/Option。
3. AST 节点和 VM 指令必须采用明确的计费约定。If 的编译辅助 JUMP 不应被无说明地算成额外语义工作，否则可能破坏既有两后端一致性的范围。短路实际未执行的分支不收取求值费用，但输入形状验证仍需完成。
4. Eq、InSet、Record.get 和规范化产生 frozenset 时的哈希/相等操作不能藏在单个“指令步”内。可采用可计量的结构算法，或在执行 Python 内建操作前收取保守上界；计费本身也必须有界。避免依赖随机哈希遍历顺序产生不同的允许结论。对整数运算按操作数位宽给出成本约定。
5. 常量来自重新验证过的 IR；动态值必须在规范化后才参与比较，不能通过未验证宿主对象的自定义比较方法执行任意代码。预算保证只覆盖规定的纯解释器，不扩张为 Python 宿主沙箱或硬实时保证。

## 诊断与离线证据

`Predicate.values` 目前把 Reject/TypeError/ValueError 合并为 EVALUATION_TYPE_OR_RANGE；需单独透传预算耗尽，保留源节点、需求编号及安全的工作量统计。`CompiledContract.evaluate` 应保留已完成条款的真实状态，并将未完成条款记为 Unknown，整个动作拒绝。

有限枚举目前直接调用两个 evaluator；须捕获预算耗尽，停止签发 BoundedChecked/等价结论。SMT 编码描述理想纯语义，没有运行预算语义；必须明确证明条件，或增加预算模型，不能将语义 Unsat 自动推广成有界实现的无条件等价。Sat 的实际回放若因预算失败，应保留求解结果 Sat，但属性为 Unknown；不能把同一个资源失败当成发现逻辑反例。

## 验收证据

- 恰好足够/差一单位、错误类型、大量非法 Record 字段、嵌套集合、深记录、字符串和大整数等探针。
- AST/VM 的成功结果与预算失败范围一致性；短路与未执行分支；多条款共享预算且 forbid 不将 Unknown 放行。
- prepare/dispatch 原子失败，以及数据库重开后的操作/许可/账本/outbox/批准/去重不变。
- 有限枚举与 SMT 证据的 Unknown 分类和声明范围；旧 F1—F4、并发 M1、完整持久后端回归继续通过。
- 记录工作单位定义、运行版本、源摘要和真实输出。完成后重新逐项审计 M1，不仅修改门槛文字。
