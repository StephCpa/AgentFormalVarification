# 合约联合 SMT 与冲突诊断 v0.1

对应详细设计 §8.2、§8.3、R13/R15。`avcl/contract/0.3` 的已有字段和行为不变；离线后端读取同一合约 IR，重新检查类型、生成每条检查器，在共享输入环境中组合匹配条款。不存在自动删除条款、签名、激活、修改 Health 或执行外部动作的路径。

## 检查范围

每个工具分别建立下列组，同名输入字段在同组中使用同一符号值，不同工具有独立输入环境。

|组|输入和条款范围|假设有效期|
|---|---|---|
|prepare / dispatch|匹配该事件的全部 safety 条款|这些条款引用的假设|
|publication|同一输入同时满足 prepare 与 dispatch，条款去重|所有合约假设，包括未被条款引用者，与当前 PolicyAuthority 依赖检查一致|
|close|匹配 close 的 completion 条款；没有此类条款时不生成组|completion 引用的假设|

requires/invariant/success 要求谓词为真，forbid 要求为假。completion 不并入准入或发布共同见证。跨 prepare/dispatch 的字段类型不一致时，publication 组报告 Unknown/编码错误；不会改变字段域来获得可满足结果。close 的可满足输入不等于任务可完成，更不替代当前任务关闭协议中的结果、费用、义务检查。

合约假设声明目前只有来源、作用域、有效期和监控器，没有可执行假设表达式。因此本后端检查这些声明的有效期相容性，并显式假设健康观察均为匹配声明的 Healthy。时刻为 `[0,10^18)` 内整数；publication 还保留至少一个后继时刻作为可能的发布到期时间。示例与见证只使用这种假设观察，不读取、制造或替换宿主当前健康事实。

## 三项局部性质

每组分别报告输入域非空、合约 AST/生成检查一致性、共同允许输入存在性。输入域包含完整字段范围和合法时刻，不先加入条款或假设有效期，从而不会把互相冲突的假设当成空背景后证明通过。

共同允许查询为 `D ∧ 所需假设有效期 ∧ 每条已定义的允许条件`。Sat 见证必须解码、归一化，并在真实 `CompiledContract.evaluate` 中按事件回放；publication 同时回放 prepare、dispatch 和全部假设依赖。Unsat 且 D 已确认非空时，此存在性质为 Violated。AST/VM 不一致的 Sat 模型也必须经过实际求值器回放。求解器状态和性质状态分开；无法确认输入域、求解超时、编码失败或模型不能回放均不产生 ProvedUnder。

这里证明的是候选输入和假设时刻的条件存在性，不是发布成功、当前业务请求可执行或未来活性。真实工具/验证器注册、独立需求审阅、签名、当前健康、冻结条款兼容性、旧版本政策、账本承诺和能力准入继续由原有宿主流程检查。`account_limits` 虽绑定在合约摘要中，本次不求解当前账本能否接受它。

## 不可再删减的冲突集

每项约束以 `clause/<id>` 或 `assumption/<id>` 标记，目录提供需求编号、来源节点、条款摘要及假设声明。先确认完整联合查询 Unsat，再逐项试删：删除后仍 Unsat 的约束可从诊断集移除；Sat 模型需在具体谓词/生成检查及假设有效期判定中回放。

最终保留：

- 一个对最终冲突集给出 Unsat 的具体查询；固定背景是完整输入类型域和合法时刻。
- 每个剩余约束的一份必要性见证：删去它后，其余最终约束在真实求值器中全部满足。早先对更大子集得到的见证，会再次用于最终子集回放。
- 每次试删的查询、模型、求解状态及子集成员。原合约和完整失败查询始终保留。

仅当这些条件齐全时，`minimality=InclusionMinimal`，表示“再删除任意一项都会变为可满足”。它不表示所有可能冲突集中基数最小，也不列举全部冲突；`minimum_cardinality_claimed=false` 明示这一边界。资源不足或必要性见证不能回放时，已经确认的联合 Unsat 仍支持 Violated，但最小性为 Unconfirmed。诊断子集中的删除没有政策变更含义；其中的见证不能用来授权完整合约。

## 资源与证据

沿用 [纯谓词编码和可信计算基](smt-profile.md)。默认每查询 5000 ms、rlimit 1000000；整份合约共用 100000 编码步骤、512 次 solver.check 调用、30000 ms 求解调度时间预算。每个查询的超时限制取剩余时间与单查询限制的较小值。时间预算在编码完成与查询边界检查，不是 Python 进程或原生库的强制墙钟隔离。

预算耗尽后不执行后续查询，并记录 `executed=false`；未生成 SMT-LIB 的条目不伪造查询哈希或文件。`solver_calls` 统计实际调用，不把跳过的组当成通过。冲突诊断与正常查询共用预算，较大的合约可以留下 Unknown/Unconfirmed，不能因此自动缩小输入域。

输出是 `unsigned-offline-evidence`：规范合约、生成检查、逐性质报告、约束目录、逐查询 SMT-LIB、模型与回放、必要性证书、文件 SHA-256 清单。报告绑定合约/来源/规格、各条款 IR 与 checks 摘要、工具版本、假设、资源和输入边界。任何已有输出目录均拒绝覆盖。报告的 `witness_ref` 是指向当前 bundle 的 JSON Pointer。

```powershell
# 在 avcl 目录，已安装 requirements-smt.txt
.\.venv\Scripts\python.exe scripts/verify_smt.py --contract path/to/contract.ir.json path/to/new-evidence
.\verify.cmd --smt
```

命令返回 0 表示本次所有局部性质 ProvedUnder；1 表示至少一项 Violated/AssumptionBroken；2 表示只有未决结果或输入拒绝。冲突集最小性应单独读取，不能由退出码推断。候选政策修订仍须经过原有发布流程。

## 验证与剩余工作

测试包含默认退款合约、单项可满足但联合冲突、跨 prepare/dispatch 的共同见证、forbid 极性、独立工具、completion 隔离、不重叠假设有效期、未引用假设的发布依赖、字段类型冲突、编译器变异、求解/编码预算、必要性模型失败、CLI 和导出查询重放。32 份布尔条款组合以实际合约求值器穷举两个输入与四个时刻，对照三个组的非空性；这仍不是所有合约的机械精化证明。

`contract-smt-pipeline` 冻结兼容、联合矛盾、事件各自可行但无法发布、假设冲突及冲突诊断预算不足五组示例。后续仍需实现一般假设表达式、状态转移 VC、触发器可达性、任务完成可达性及部署边界；不能用本次冲突诊断替代完整 §8 或 M1 验收。

## 运行资源条件补充

联合查询仍描述理想合约语义，不编码[运行工作量预算](evaluation-budget-profile.md)。报告显式附加资源足够条件及运行时预算义务。实际 Sat 回放按事件共享 AST/检查预算；超限保留 Sat，但属性为 Unknown。冲突子集的见证回放也受限，无法完成时不确认最小性。此条件不把静态证明变为授权，不免除运行时检查。
