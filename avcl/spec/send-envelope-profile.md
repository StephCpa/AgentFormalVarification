# 退款发送鉴权信封

状态：2026-10-26，`avcl/send-envelope/0.1`，固定本地退款接收者。对应详细设计的完整绑定、发送准入、适配器身份与出口契约，以及 R01/R02/R14/T02/T18。该原型补强发送窗口中的报文不可修改前提，不代表完整 StrictRefund 发布门槛或生产身份隔离已经完成。

## 授权对象与消息格式

[`send_envelope.py`](../avcl/send_envelope.py) 使用 HMAC-SHA256 对规范化 JSON 的全部正文鉴权。签发前必须有真实已准入的本地操作，且当前参数重算出的 binding 等于已登记操作的冻结 binding；仅把一个 Prepared 对象的 admitted 改成 true 不会得到发送授权。

|字段|绑定内容|
|---|---|
|format / action / profile|信封版本、send 用途、固定发送窗口配置|
|key_id / tenant / receiver|密钥版本、本地租户、固定接收者 refund-simulator|
|operation_id|原始逻辑操作 UUID，不随重试变化|
|request / request_digest|完整请求及其摘要，包括主体、任务、业务键、订单/版本、目的地、本金、费用和版本字段|
|binding / contract_digest / epoch|冻结许可承诺、历史合约摘要和准入 epoch|
|issued_at / not_after|本次尝试签发时刻及原操作冻结截止；重试不能延长|
|attempt|同一逻辑操作的发送尝试序号，受当前固定上限约束|
|signature|HMAC-SHA256 十六进制鉴权码；不是公钥数字签名|

正文遵循现有 64 KiB 受限规范化编码：精确字段集、拒绝重复键、数字只用规范十进制字符串、UTF-8、固定工具/币种/版本。接收端先检查鉴权码，再独立验证作用域、完整请求摘要、时间顺序、尝试范围及字段形状；来自持钥方的畸形消息也不能跳过结构检查。

## 密钥边界

发送专用密钥按 `HMAC-SHA256(authority_key, "avcl/send-key/0.1" || NUL || canonical({tenant, receiver}))` 派生。正文鉴权使用另一个固定域 `avcl/send-authentication/0.1`。因此发送验证器不持有政策签发主密钥，政策信封与发送信封不能直接互换。

`kernel.trusted.send_verifier()` 是受信宿主的测试配置入口，返回仅供接收端使用的验证器。内存主密钥随实例生成，PostgreSQL 从既有 authority 行恢复，所以同一测试库重开后派生出相同接收密钥。没有新增密钥导出 HTTP 路由，不把派生密钥写入证据包。

HMAC 验证方也持有可以生成同域鉴权码的共享密钥。这里不提供不可抵赖性、公钥发布者身份、KMS/HSM 隔离、密钥轮换或泄露恢复。测试宿主可以访问 Python 私有属性与数据库 authority 行；不可信 Agent 不能持有这些对象或解释器权限。生产配置仍需可信密钥分发、权限隔离、真实接收端身份和安全传输。

固定 receiver 是一个逻辑服务域，须对应同一个去重存储域。多个独立服务实例若错误配置成同一 receiver 和共享密钥、却各自保留独立去重记录，不在本原型保证中。完整注册表与真实 endpoint 绑定仍需实现。

## 与事务和恢复的连接

共同发送门禁 `admit_attempt` 继续检查时间余量与次数上限，随后生成鉴权信封，并把信封摘要写入同一个 SendAttemptAdmitted 事件。内存工作流、持久工作流及 outbox 领取共用此逻辑；签发结果只有在持久事务提交后才返回给发送调用方。

`claim_outbox` 的宿主结果新增 envelope 字符串；operation、worker、generation 保持原语义。持久工作流的 Send I/O 意图也返回 envelope。原始信封是截止前可重放的操作授权，不应作为普通日志公开；数据库审计只保存摘要，不复制整个信封或鉴权密钥。

领取事务提交前进程退出，不留下发送尝试；恢复后重新领取从尝试 1 开始。提交后进程退出但信封尚未交给发送方，仍按不确定写入处理；保留已提交尝试、预算和核对责任，不因为没有拿到信封而自动再签发或重发。

同一操作可以有多个在窗口内签发的尝试信封，其 issued_at、attempt 与鉴权码不同，但 operation_id、请求与 binding 不变。接收端仍依靠同一逻辑操作去重，不能把每张新信封视为新的退款业务。

## 接收模式与失败语义

RefundService 增加显式 verifier 配置。该鉴权模式要求同时启用有限保留和显式时钟，只接受 JSON 信封，拒绝原始 Operation 对象；执行器根据宿主配置向此模式传输信封。原有未配置验证器的模拟服务保留原接口，便于维持既有模型边界。鉴权失败不会自动改用未鉴权接口重试。

消息到达时同时检查 MAC、接收作用域、签发时刻和冻结截止。有限去重记录删除后，原信封仍因已过期被拒绝；攻击者修改 not_after 则因鉴权码失配被拒绝。服务端可以在不永久保存每个操作的去重记录的前提下拒绝旧报文，但这依赖密钥、可信时间及冻结消息的前提。

正常的窗口关闭/保留期不足继续作为“这次请求未被接受”处理，不能推出历史无效果。鉴权错误在两个工作流后端均导致 Halted、保留 Unknown 预算并隔离新支出。独立宿主 outbox 消费者仍须把适配器错误交给事故处理流程；本次没有新建常驻发送服务。

本版请求授权用途仅为 send。鉴权模式的取消入口明确拒绝 SIGNED_CANCEL_UNSUPPORTED，不能拿 send 信封当作取消授权；查询仍为受信宿主只读入口。后续接入的 [回执鉴权](receipt-envelope-profile.md) 使用独立回执密钥，鉴权服务的 send/query 返回 JSON 回执，经 TrustedPlane 核验后才结算。用途独立的取消鉴权和远端网络服务仍待完成，不能由请求 MAC 推导其已完成。

## 可复现验收

单元测试检查所有关键绑定字段篡改、请求目的地/金额修改、原始对象绕过、不同主密钥、同密钥下租户/接收者不匹配、政策/发送用途分离、重复 JSON 键、数字格式、大小上限、签发前有效期、合法重放与过期后伪造延期。也检查双方工作流在鉴权失败时不降级发送。

真实 PostgreSQL 测试覆盖同库重开后的验证与签发、领取事务提交前后进程退出、完整工作流传输 JSON 信封、传输参数篡改零效果且保留预算，以及远端记录删除后的过期/篡改信封拒绝和迟到回执结算。

`verify.cmd --postgres` 同时运行完整回归和 `send-envelope-demo`。其 `send-envelope-report.json` 提供篡改拒绝、合法效果、幂等重放、记录到期、非法延期与最终结算的逐步实际费用/本地账本轨迹，只输出信封摘要，不输出鉴权码或密钥。此示例使用独立模拟效果 oracle，与真实生产服务验证分开报告。

后续仍需将请求/回执鉴权模式纳入正式工具注册与合约发布门禁，完成生产身份/endpoint 绑定、取消用途、密钥轮换、TLS、真实时钟及全中介部署。当前 P1/P2/P4/P7 的抽象 Lean 证明没有因此自动扩展为该 HMAC 协议或 Python/SQL 实现的机械安全证明。
