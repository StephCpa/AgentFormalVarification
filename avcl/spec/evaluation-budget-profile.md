# 有界运行求值

实现详细设计 §4.3 的纯求值资源门禁。工作模型版本为 `avcl/evaluation-work/0.1`，默认 **4,000,000** 单位，宿主配置上限 **16,000,000**。这是确定性的保守工作计数，不是毫秒、CPU 指令或内存总量保证。原纯值语义和 IR 摘要不变；资源不足可以拒绝本来满足纯逻辑的输入。

## 预算的传递

`WorkBudget` 仅由宿主建立，不接受候选 JSON 指定。限额必须是 0 至上限的整数，布尔值、负数、字符串和更大值拒绝；0 表示不允许执行求值。`budget=None` 创建默认预算，并非关闭限制。耗尽状态不可通过后续零成本调用清除。

预收费不足时，used 饱和至 limit 并置 exhausted；这一统计包含保守预留的工作额度，不表示这些 Python 操作已经全部执行。若同一报告同时存在已确认的 AssumptionBroken 与后续预算 Unknown，授权错误代码优先保留 ASSUMPTION_BROKEN，条款报告仍保留各自状态。

`Predicate.values/evaluate`、`Checks.evaluate` 和 `CompiledContract.evaluate` 均接收同一个可选预算对象。输入规范化的递归调用继续使用该对象。一次 `ReferenceKernel._authorize` 的内置退款谓词和全部合约条款共享预算；不会给每个条款重新发放额度。PostgresKernel 将宿主限额传递至每次恢复的参考内核。该配置是部署资源配置，不是用户能力，也不持久化为旧操作的新授权。

独立纯调用与工作流分支检查默认同样有界。编译、JSON 解码、策略加载、数据库 I/O 和纯求值之外的请求处理不包含在这一计数器中，仍受各自的静态/协议边界约束；不能从本计数器推出整个服务请求的实时上界。

## 工作单位

- 每个 AST 节点和每条 VM 指令收取 1 单位。AST 的 If 选择 true 分支后另收 1 单位，对应编译器生成的分支汇合 JUMP。VM 的 JUMP 也计费，故即使内部损坏形成跳转环也会耗尽，而非无限循环。生成程序仍由重新编译比对验证。
- 规范化先检查精确类型及廉价长度上限，再扫描字符串、字段和子值。Record 字段数不匹配立即拒绝，不先遍历巨量 entries。字符串按字符数、大整数按位宽计费；名义类型先检查 name/value 的类型，避免调用未知对象的比较方法。
- Record 字段查找、字典转换及字段排序预收字段数量和键长度的保守成本。已经规范化的不可变 Record/Some/Set 可以直接保留；需要重建集合时，在哈希和潜在碰撞比较之前预收费。
- Eq/InSet 使用下面的结构权重预收成本，计算权重本身也逐节点收费。它忽略对象同一性、缓存和有利哈希分布带来的快捷路径，不依赖随机哈希遍历顺序确定是否有足够预算。
- 加减与整数比较按操作数的 64 位抽象字数之和收费，乘法按两者乘积收费。字数定义为 `1 + ceil(bit_length/64)`，不是对 CPython 机器执行时间的证明。

结构权重 W 定义：None/Bool 为 1；整数为上述字数；字符串为 1+字符数；Tagged 为 1+名称长度+值长度；Some 为 1+子权重；Record 为 `1+sum(1+字段名长度+子权重)`；含 n 个元素的 Set 为 `1+(n+1)*sum(元素权重)`。嵌套集合的乘数反映碰撞时递归相等比较的保守成本。

Eq 收取 `W(a)+W(b)`；InSet 收取 `(len(b)+1)*W(a)+W(b)`；新集合的哈希构建收取 `(n+1)*sum(W(item))`。这些是所声明纯值实现的工作规则，尚未机械证明其对所有 Python 实现的复杂度关系。输入类型必须来自经过验证的 IR；不声称防御能修改 Python 类、私有计数器或内核对象的宿主。

AST 与 VM 保持各自的控制流解释，结构操作和整数原语通过共享的计量/执行函数实现。这个共享函数属于运行可信代码；两个后端结果相同不能单独证明它没有共同错误。已有确定结果测试、强制哈希碰撞探针和分别生成的 SMT 表达式提供不同层次的证据，仍不构成 Python 实现精化证明。

## Unknown 与事务边界

耗尽抛出 `EvaluationLimit`，公开代码为 `UNKNOWN_EVALUATION`，保留需求、源节点、限额与计数信息。规范化不再把它误并为类型错误。条款报告为 Unknown，整份合约 allowed=false；forbid 仅在求值成功后反转布尔值。已经完成的条款保留真实结果，后续耗尽条款仍为 Unknown。

prepare 超限不创建操作、许可、批准消费、去重记录或预留；dispatch 超限保留原 Prepared、许可、全部 pending 和无发送意图。数据库沿用同一事务回滚，恢复后可核对。重新给足宿主资源并执行完整检查可以成功，不把先前 Unknown 当作授权缓存。

成功的 Prepared/DispatchAdmitted 事件增加 `evaluation_work`，以现有 Event 字符串详情约定保存规范 JSON，包含模型、限额、已用量及耗尽标志。`runtime_report` 和合约报告也返回工作统计。拒绝不因此获得事务外持久日志；该项仍待完善。

## 离线验证的边界

有限枚举遇到运行预算耗尽返回 Unknown、完整域标志为 false，不签发 BoundedChecked 或逻辑违反。运行报告同样为 Unknown/allow=false。

SMT 仍编码理想纯语义，没有编码燃料。报告显式记录 `runtime_budget_encoded=false`、`evaluation-work-sufficient` 假设和运行时预算义务，因而不能把 Unsat 等价结果解释成无条件的有界实现等价。Sat 模型实际回放若耗尽，保留 solver_status=Sat，属性状态为 Unknown；这种资源失败不能成为逻辑反例。联合合约回放按事件共享预算，冲突子集回放也有界。

## 验收范围

`tests/test_evaluation_budget.py` 覆盖恰好足够/差一单位、短路与分支汇合、集合/记录/选项、强制哈希碰撞、大整数、巨量非法 Record、集合重建、共享条款、forbid、有限验证分级、prepare/dispatch 原子失败及内部跳转环。普通 64 元素记录集合在默认限额内通过；一个仍小于 64 KiB 的合法嵌套集合在默认限额下 Unknown，在允许的更高宿主限额下两个后端均为 true。默认值因此有明确的正例与超限例，不以“AST 很小”放过数据处理成本。

`integration/test_evaluation_budget.py` 检查真实 PostgreSQL 的 prepare/dispatch 超限后，操作、许可、批准、业务防重、请求防重、outbox、审计和账户全部不变；用新内核重读后再次确认。SMT 测试包括故意错误字节码的 Sat 反例在预算不足时保持 Unknown。`--m1` 纳入 5 项定向预算检查，仍不签发 M1 发布结论。全量结果以新 evidence 记录为准。
